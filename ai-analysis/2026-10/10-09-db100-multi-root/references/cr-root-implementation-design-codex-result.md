## Q1 — workspace discovery

**Verdict: combined, config authoritative; safe auto for obvious layouts only.** Proposal in `crates/code-reality/src/profile.rs:19,46-52,56-80,128-164`: add optional top-level `rust_projects = ["relative/root", ...]` to `.code-reality.toml` and to `VALID_KEYS`, distinct from existing `[[scan_root]]` (which serves Python/boundary scanning). Treat a present empty array as configuration error, not an instruction to omit the Rust leg. No fixed directory names. Do not introduce `--rust-root` until a use case needs a second source of truth; the config is durable and available identically to `build`, `freshness`, and auto-heal. Explicit `--producer rust` continues to select the Rust *family*, within which all resolved projects run.

Resolve once via a pure `RustProjects::resolve(repo, profile)` module (suggest `src/rust_projects.rs`), reused by the build path and the freshness/identity path. **Do not spawn `cargo metadata` on every hot `freshness` call** [inferred design tradeoff]; parse TOML locally and use build-stage Cargo metadata as an additional authority for real member/workspace semantics. Parse errors and unsupported member patterns must fail closed, not return a shortened root list. For configured paths, require a nonempty, relative, canonicalizable directory; reject absolute paths, `..` segments, symlink escapes, duplicate aliases after canonicalization, and ancestor/descendant pairs. Map canonical paths back to slash-normalized *repo-relative* paths, sort deterministically. Allow `"."` for a repo-root workspace. Each candidate must have a parsable `Cargo.toml` and resolve as an actual Cargo **workspace root**, not just a package member: `cargo metadata --no-deps --format-version 1` `workspace_root == candidate` is the build-stage oracle; include the metadata stderr in failure. Preserve single-workspace behavior when no config is present.

Auto mode: (a) if repo root has a Cargo.toml, use `"."` **only if no other independent workspace is discovered**; nested independent roots inside a root workspace would violate the non-overlap contract, hence fail. (b) If root has none, inspect immediate child directories with Cargo.toml; accept `N ≥ 1` roots if every candidate declares an explicit `[workspace]` and metadata agrees, as `delegate-bridge/rust/Cargo.toml:1` and `delegate-bridge/dutymail/Cargo.toml:4` do [verified]. Preserve the historical one-child standalone `[package]` case after confirming it is its own workspace root; with multiple implicit-package candidates, or a mixture of implicit-package and explicit-workspace candidates, demand an explicit `rust_projects` list. A child *member crate* whose `workspace_root` is its parent is not a new root; if it is mistaken for one, reject. For explicit config, also scan for other independent immediate-child `[workspace]` candidates and reject unlisted ones: adding a third sibling must not silently retain the old two-root coverage. Deeper standalone roots need explicit config; if they have Rust files outside all selected roots, fail the document-coverage gate (Q2). Git-root plus nested disjoint workspace roots are deliberately out of scope under the mandated non-overlap rule.

**Required diagnostic strings** (proposed contract; `BuildError::Env` / CLI exit 2; freshness resolves to check-failure/exit 2 rather than `fresh=true`):

## Q2 — SCIP document path anchoring and rewrite

**Empirical result [verified]:** ran the installed **rust-analyzer 1.96.0** (`ac68faa2`) with:

```text
rust-analyzer scip /Users/ctai/Github/delegate-bridge/dutymail --output /Users/ctai/Github/code-reality/.agent-tmp/db100/scratch/dutymail-probe.scip
```

Exit **0**, 6.6 MiB emitted. `strings -a ... | rg 'crates/dutymail-(cli|core)/src/(main|lib)\.rs'` returned `crates/dutymail-cli/src/main.rs` and `crates/dutymail-core/src/lib.rs`, with no `dutymail/` prefix. The raw SCIP output also printed numerous rust-analyzer `Duplicate symbol` diagnostics *within this one workspace*; they did not fail its producer command. Thus workspace-local duplicate symbols exist in the real producer, which is why the new collision gate must distinguish **cross-project conflicting definitions** from existing within-project duplicate targets. `strings` confirms the bytes/path form; [inferred] that **every** `Document.relative_path` of this producer follows the same workspace-relative convention (this leg did not protobuf-dump all documents). No two-root merged SCIP or real root graph was built during this advisory.

**Normalization point:** after each `stage_rust(project_root, individual_part, roots)` succeeds and before Rust pre-concat (`src/build.rs:374-406,192-199`), parse the actual `scip::types::Index` protobuf, rewrite each `Document.relative_path` using `project_root_relative_to_git_root.join(old_relative_path)`, and write the normalized bytes back to this attempt's staged partial. Example: `crates/dutymail-core/src/lib.rs` → `dutymail/crates/dutymail-core/src/lib.rs`; the other root similarly prefixes its own relative root. Revalidate protobuf, existing-doc membership, and nonempty relevant documents after rewrite. **Never prefix the symbol IDs**: cross-document references use those IDs. Keep and attribute the original project root in a separate build receipt / per-part evidence, not a new symbol namespace.

Reject absolute or empty paths, `.`/`..` components, non-normalized separators or traversals, symlink escapes after canonicalizing the resolved file, nonexistent/nonfile paths (for document-bearing Rust source), collisions between normalized *document paths* (within and across parts), and documents that resolve outside the selected project subtree. Explicit diagnostic `Rust SCIP document '<raw>' from project '<root>' normalizes to invalid/colliding repo path '<rel>' (conflicts with project '<other>')`. Preserve source text and paths unchanged; rewrite SCIP only. A producer may legitimately omit some source files; compare the *governed* Rust source walk with normalized produced document paths before permitting an authoritative v2 stamp. Missing coverage must not masquerade as full-success; for the composed-root feature, fail before publishing if required Rust source docs are missing (or explicitly reject the unsupported corpus policy) rather than silently creating an unstamped/legacy plane.

This validation is necessary because `src/graph_db.rs:795-809,871-874` resolves each SCIP relpath as `repo_abs.join(rel)`; without the rewrite, both the node file paths and caller edges point under the wrong root. `src/engine.rs:1187-1205` currently conditionally stamps comparable provenance only if produced document paths exactly match captured disk docs; wrong prefixes also prevent this equality. ## Q3 — pre-concat, not general staged-multi-leg

**Verdict:** one staged leg per family remains the orchestration contract. `src/build.rs:204-207` stores just `family, path`; `:432-466` takes `staged.iter().find(...)` at `:446` and would **silently discard** the second Rust leg. Changing that generic merge to support repeated family legs widens its blast radius to every family, its `staged.len()==1` fast path, face labels, and future reuse. Since only Rust currently needs N calls, do this inside the Rust leg:

```text
RustProjects::resolve(repo) -> sorted, unique roots
for (ordinal, root) in roots:
    stage_rust(root, attempt_dir/<ordinal>-raw.scip, bins)
    validate_partial + parse/rewrite + path/coverage/cross-part collision checks
first normalized part -> attempt_dir/rust-composed.scip
for each remaining normalized part: concat_scip(rust-composed.scip, part)
validate combined Rust index, including expected documents
staged.push(StagedLeg { family: Rust, path: rust-composed.scip })
... existing ORDERED python/rust/typescript merge_and_publish ...
```

Use a unique attempt subdirectory already provisioned at `src/build.rs:509+` / cleaned at `:409-424`; `concat_scip`'s fixed `.merge-tmp.scip` sibling (`:192-198`) is then per-attempt isolated. Do not call `concat_scip` on the **live slot**. Keep sorted root order, including when config order changes; `Index.metadata` singular fields are last-value-wins under protobuf concatenation (`src/build.rs:17-22`), and provenance is the sidecar (`:744-766`). Keep `rep.face = "rust-face"` for a Rust-only composed build and `mixed(python+rust+typescript)` for three producer families. Report `rust-analyzer <version> [roots: <sorted roots>]` and one success/error per project; an error names the root + process status/stderr, and the old live slot stays untouched. `src/build.rs:717-722` already publishes only after staging.

**Collision policy:** before pre-concat, scan Rust **DEF** occurrences (SCIP definition bit in each document), map `symbol -> {(workspace_root, repo_rel_path, definition_position)}`, and reject a symbol defined in **different workspaces at different source locations**. Error `Rust SCIP symbol collision '<symbol>': <workspaceA>:<pathA>:<line> vs <workspaceB>:<pathB>:<line>`. Keep the old handling of same-workspace duplicate targets unchanged for this card. Do not deduplicate cross-project definitions on merge, or silence them via symbol prefixing: refs would become semantically inconsistent. `src/graph_db.rs:176-178,780-818` currently uses `nodes.symbol UNIQUE` and `INSERT OR IGNORE`, hiding the second DEF. The acceptance oracle should count *queryable distinct definition symbols after each workspace's established internal dedup policy*, verify cross-project intersection is zero or has an explicitly adjudicated shared physical definition, and assert full merged graph `node_count == |A ∪ B ∪ JS/TS ∪ Python queryable DEF symbol sets|` with paths. A raw count of occurrences is an invalid oracle (the empirical Rust producer prints within-workspace duplicate symbol diagnostics).

## Q4 — source identity and topology are one trust boundary

**Present defect [verified]:** `src/engine.rs:610-680` inserts a record only after `LanguageFace::from_path` succeeds. `src/language.rs:36-47` handles .py/.rs and the six JS/TS extensions only. `Cargo.toml`, `Cargo.lock`, `.cargo/config.toml`, and `rust-toolchain.toml` are therefore absent. `src/engine.rs:1045-1076` hashes `walk.records()` and stores the `.code-reality.toml` hash **only in the in-flight `ProductionIdentity.profile` equality guard**. The query-side `evaluate_staleness` recomputes only `walk.records()` / `source_faces` (`src/engine.rs:910-960`); `js_ts_profile_fingerprint` only hashes JS/TS excludes (`:756-777,873-883`). Consequently a Cargo-only change can leave a v1 `fresh=true`, and a changed `rust_projects` profile section can be invisible after publication. The GLM assertion that the entire Rust walk already covers manifests is demonstrably false.

**Required v2 identity inputs, governed only when Rust is in the stamped/current face scope:**

1. All selected workspace-root `Cargo.toml` and `Cargo.lock` when present; **every** `Cargo.toml` in its effective workspace-member tree (including crates with manifests below `crates/`); any nested `Cargo.lock` actually participating in Cargo resolution. A changed membership declaration and newly arrived manifest are observable. Track root lockfile **absent/present** in topology data, not just its bytes when present. Conservative inclusion of all Cargo.toml inside the chosen workspace roots is acceptable if member discovery cannot cheaply disambiguate; this causes safe false-stale, never false-fresh.
2. Repo/workspace-scoped `rust-toolchain`, `rust-toolchain.toml`, `.cargo/config`, `.cargo/config.toml` at the effective ancestor locations **inside the git root**, plus their existence markers. Root `.code-reality.toml` bytes when it exists; missing/present marker otherwise. These files influence Cargo/RA compilation/discovery; track their exact repo-relative names so a rename counts.
3. A domain-separated, root-independent **topology descriptor** containing normalized sorted selected project roots, resolved workspace-member roots, explicit-vs-auto discovery mode, and exact relative expected input-file paths with absent/present markers. Include independently detected unselected workspace candidates as a fail-closed validation step, not as quietly ignored data. Root *order* from TOML is not semantic; sorting identical sets keeps identity equal. Added/deleted workspace/manifest/lock or updated membership changes the digest even if no `.rs` changes.

**Placement:** extend `SourceWalk` in `src/engine.rs:516-604` with a separate `rust_inputs` record map, constructed through the shared Rust project resolver and file walker. Its existing `rs`/`paths_for_faces`/SCIP doc-set remain **source documents only**; never put Cargo manifests into `rs` or the doc equality at `src/engine.rs:1187-1195`. `records()` used by `ProductionIdentity::capture`, `evaluate_staleness`, and cache repopulation (`src/build.rs:806-817`) must additionally expose `rust_inputs` as `LanguageFace::Rust` identity inputs, sorted by repo-relative path. Update Rust-scoped `newest` for legacy signals but keep `fingerprint_for_faces` and doc-count semantics explicitly separated from input records. Feed the same deterministic topology descriptor to `compute_identity()` in `src/identity.rs:271-315` (new typed input parameter or a `rust_input_manifest` value in the capture object); do not invent dummy `.rs` SCIP docs. Crucially, `ProductionIdentity::capture`'s A/after/locked comparisons (`src/build.rs:551-554,659-674`) must cover the same topology and config bytes before and after production, so a root arriving mid-build cannot publish a partial index.

**Versioning contract:** bump `src/identity.rs:32-37` `IDENTITY_ALGO = "sha256-v2"`, domain header to `cr-identity-v2\0`, and per-file cache schema/version (or discard v1 cache on algo mismatch). v2 composition remains content-based: `SHA256(header-v2 || sorted source/input records (face, rel, size, SHA256(bytes)) || domain-separated sorted topology and presence markers)`. No absolute checkout path, mtime, iteration order, or Cargo metadata timestamp enters the hash. TC-1a remains: **same repo-relative files+content+topology in different checkout locations => same v2 identity**. A one-time digest change on unchanged `.rs` trees is expected and warranted because v1 omitted producer inputs. Full rebuild restamps v2 against the newly composed index; changing the v1 digest silently while leaving the `identity_algo` label at v1 is unacceptable.

`src/engine.rs:910-960,741-753` currently interprets a mismatched identity algo as *legacy*, which can return `needs_rebuild=false` based on weak mtime/doc signals. **Add explicit `identity-algo-upgrade` / `rust-provenance-required` stale reasons and make them fatal to Rust-inclusive `freshness` and query auto-heal, including metadata missing comparable identity**; do not allow a v1 or legacy Rust index to claim current-tree after Cargo-only edits. Preserve existing non-Rust legacy policy if desired. `src/freshness.rs:95-136` must return exit 1, `serves=committed-baseline`, `fresh=false` until a complete v2 build; incompatibility must not be reported as `legacy-signals` with `fresh=true`. A `freshness` check encountering an invalid/ambiguous Rust topology returns exit 2, with no truth claim. Tests must freeze both the new downgrade behavior and the v2 positive case.

**`--stamp-meta` correction [verified]:** `src/cli.rs:465-469` calls `engine::stamp_meta_core`; `src/engine.rs:1101-1110` invokes `stamp_meta_locked(..., validated=None)`; `:1159-1209` **only preserves previously byte-bound comparable identity for identical index/repo/selection**. It does **not** call `ProductionIdentity::capture` to certify current sources and must **not** be changed to do so (anti-laundering). The normal `build` passes `Some(&production_a)` (`src/build.rs:751-766`) and owns v2 consumption provenance. Under v2, manual/head-only restamp cannot upgrade v1 or a modified Cargo input to v2. Update tests and `--stamp-meta`/`refresh` documentation around this already-intended distinction.

Limits [unverified]: Cargo variables supplied entirely from the shell, global `$HOME/.cargo/config.toml`, external toolchain upgrades, and exact nanos+size cache forgery need separate provenance policy; do not claim v2 observes outside-repository environment bytes. Existing `src/build.rs:906-911` explicitly leaves rust-analyzer binary version out of strict producer drift tracking.
