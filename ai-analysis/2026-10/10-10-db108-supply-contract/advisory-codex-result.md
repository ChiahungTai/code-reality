## Additional gaps / bridge-facing failure modes

1. **Installed executable ≠ checkout ≠ data plane.** On this machine PATH main `0.10.0+cf0dc74-dirty`, uv main/bridge `0.10.0+28f6858`, and stamped SCIP index `0f1af4c`. Freeze separately: `provider`, absolute binary path + executable digest + `--version`/rev, MCP handshake/tools schema digest, target repo root, freshness verdict and source identity. Do not equate any two of these.
2. **The active repo currently fails freshness.** With an `identity-algo-upgrade` legacy slot, stamped/current identities are null. If bridge policy requires fresh source graph, return typed stale/unavailable with this evidence; no opportunistic graph heal in read-only/advisory legs.
3. **Provider launch semantics differ.** `code-reality-mcp` **without** `--stdio` starts streamable HTTP on `127.0.0.1:8200/mcp` (`bin/code-reality-mcp/main.rs:1-5,44-51`). LSP bridge serves stdio (`src/bin/code-reality-lsp-bridge.rs:18-26,89-93`). The bridge must supply exact argv, cwd, env, bounded initialize/list timeout, and explicit mode.
4. **Version check is not ABI verification.** Wrapper's `"$want+"*` admits `-dirty` and different revisions. A digest derived from the **running** tool schema, plus pinned publisher-supported ABI, is needed; tool **count** or `rmcp` serverInfo cannot substitute. A publisher artifact must be independently bound to the binary.
5. **Not all MCP tools are read-only.** Main MCP registers `build`, `snapshot`, `delta_tour`, `project` that write data-plane/reports (`mcp_server.rs:283-315,861-925`). Do not expose them in a read-only job based on a successful `tools/list`. `lsp-bridge/edit_file` is *in-memory* and can alter LSP session state despite no disk change (`server.rs:221`). No write tools were invoked in this leg.
6. **Lazy LSP behavior hides absent dependencies.** Presence of the 4-tool LSP server proves neither `pyrefly-lsp`, `rust-analyzer` nor `typescript-language-server` is installed and responsive. Check per-family `lsp_status` and real requested operation when needed; `session.rs:381-410` can fail at lazy first spawn. Run from target repo cwd.
7. **Output/error contracts matter.** Tool outputs are text, with `[STDERR]` appended, capped at 1 MiB plus truncation marker (`mcp_server.rs:218-245`), and tool-level failure may be an error result or `is_error` (`tests/s6_mcp_server.rs:142-158`). Consumers must handle both without treating a completed RPC as valid structural evidence. Cancellation does not guarantee that already-started write tools have stopped (tool descriptions `mcp_server.rs:861-903`).
