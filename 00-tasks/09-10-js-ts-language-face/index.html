Why this arc exists

CR can currently build production graphs for Python and Rust, but a JavaScript repository such as delegate-bridge has no supported build leg. Planning POCs show that CR already parses scip-typescript output; the remaining work is semantic and lifecycle integration rather than a new graph engine.

POC: format

Existing CR ingested the governed 28-document JS SCIP: 192 nodes / 293 edges, and real cross-file callers already resolve.

POC: semantic gap

Every JS node was mislabeled Rust and every graph edge was REFERENCES; CALLS = 0. S3 closes language, symbol-kind and call-site semantics.

POC: exact corpus

Upstream --infer-tsconfig and empty {} config fail the real .mjs corpus. A CR-owned explicit files config indexes exactly 28 source documents without target config mutation.

POC: six extensions

Glob/include inference missed .jsx; explicit governed files indexed .js/.jsx/.mjs/.cjs/.ts/.tsx exactly.

POC: CALLS

Tree-sitter JavaScript/TypeScript candidates classified direct, method, optional-chain and constructor calls across all six extensions while preserving property reads.

POC: LSP

typescript-language-server --stdio passed hover for all six extensions and diagnostics/edit convergence. The bridge therefore needs executable + argv, not a third bare command string.

POC: containment

enclosing_range coverage was 192/192 on source-only dogfood and 10/10 on the six-extension fixture.

POC: freshness

mtime-only Stage A can miss delete/rename. S4 adds active-face/source-set/profile corpus identity so path-set changes force rebuild.

Two milestones

  • M1 structural: build, atomic all-leg staging, refs/callers, graph CALLS semantics, freshness/self-heal, graph queries, and fail-loud guards for language-specific tools.
  • M2 type: all six JS/TS extensions routed to an independent LSP backend for hover, diagnostics and edit/recheck.

Seven implementation children

  1. Language-set build orchestration.
  2. scip-typescript producer and governed corpus.
  3. JS/TS graph language + CALLS semantics.
  4. Freshness / doc-set / self-heal lifecycle.
  5. JS/TS LSP type face.
  6. Truthful boundaries for Python/Rust-only special tools.
  7. delegate-bridge dogfood, docs, distribution and release closure.

Non-negotiables

  • No repository-specific JS hacks in code-reality.
  • No target-repo tsconfig.json mutation; an existing config must be usable, so empty {} falls back to a CR-owned explicit governed files config.
  • No hidden npx/npm network install during build, query healing, plugin startup, or default tests.
  • Every producer leg stages before one atomic live-slot publish.
  • Producer and freshness paths consume one governed corpus policy; delete/rename/profile changes cannot be hidden by mtime-only freshness.
  • No “supported” claim while the graph is references-only, language metadata is false, or JS/TS symbols are silently filtered.
  • No false-clean hazard/audit/project output on a language those tools do not understand, including mixed repos.
  • M1 structural support is independent of the optional M2 LSP backend.
  • Python/Rust behavior remains a regression contract.
