## Shared design concerns (four groups)

1. **Bounded-time interaction with child processes (R0-03, R0-05).** These two must tell one coherent story: per-interaction transport writes are deadline-bounded and kill-recoverable (R0-05 mechanism), while whole builds are deliberately not cancellable and the contract says so (R0-03 amendment). Fixing R0-05 while leaving R0-03 undocumented (or vice versa) leaves the lifecycle story incoherent.
2. **Terminal death semantics of the LSP session (R0-04, R0-09).** The shared `dead` flag is terminal and generation-less. R0-04 makes a consumer honor it at an acceptance boundary; R0-09 stops the docs from promising resurrection. Any future same-session restart needs generation fencing in *both* — do not let one fix assume retry while the other assumes terminality.
3. **Data-plane publication atomicity and provenance (R0-06, R0-07, R0-10).** The slot/meta/graph triad is co-published with three independent holes: the stamp trusts post-hoc bytes (06), torn detection misses graph *absence* (07), and graph publication is neither serialized nor complete-at-rename (10). All three live in one neighborhood (`build.rs` publish sequence ↔ `graph_db.rs` ↔ `engine.rs` predicates) and should be adjudicated as one coherent publication design, not three patches that each reshape the sequence the next lands on.
4. **Gates that claim verification without verifying (R0-01, R0-08).** Both are prefix/skip false-positives in acceptance machinery. Mechanical fixes, but the value is entirely in the *negative* cases — a fix without negatives re-greens and re-rot.

Probe: extend `scripts/test-plugin-wrapper.sh` with 2 positives (`0.9.3`, `0.9.3+rev`) and ≥3 negatives (`0.9.30+rev`, `0.9.3-rc1+rev`, `0.9.4+rev`), asserting zero install attempts on negatives — this is the minimal defensible probe and it already exists as a harness.

**R0-02 — uncapped MCP error path (P2, Fix; agree).** *Observed*: `map_tool_output` (mcp_server.rs:257-266) builds the error text from raw stdout+stderr with no `apply_text_cap`; 1.2 MB stderr → 1.2 MB response, code `-32603`. **R0-03 — cancellation/EOF doesn't stop producers (P2; contract amendment is enough — with one escalation clause).** *Observed*: cancellation suppresses delivery but the producer completes and writes its marker; EOF leaves the server alive until the producer exits (3.05 s); runtime stays responsive. Answering the packet's question: yes, for this scope honest documentation is the right disposition. Reasoning: cooperative cancellation of a multi-producer build requires subprocess kill ownership, a cancellation token threaded through `run_module` → module `run` → build internals, and publication-rollback semantics — that is a publication-transaction feature whose blast radius overlaps R0-06/R0-10; doing it inside this round couples three fixes for a contract no consumer was ever promised. Amendment must state three things explicitly in the `build` tool description (the consumer-visible contract): (a) cancellation abandons the *caller*, not the work; (b) started work may continue **and publish its outputs**; (c) transport closure awaits in-flight work. Weak-fix challenge: a doc change that only says "cancellation stops the response" is half-true — the publish-side effect is the part a consumer could rely on wrongly. Residual/escalation: if an abandoned build's publication is ever observed interleaving with a subsequent build, that belongs to R0-10's serialization, not to a cancellation feature — keep them separated. Probe: assert the tool-description text carries the clause (description-string test or doc grep in CI); the existing lifecycle demo stays as the behavior record.

**R0-04 — dead backend + warm cache → false success (P2, Fix; agree).** *Observed*: `check_file_impl` returns `Ok(format_diags(...))` at server.rs:446-447 gated only on version/fresh/quiesce; `sync_open` no-ops for an unchanged open file, so a dead backend never surfaces; probe shows `state=dead` yet `isError:false, count=0`. Preferred: gate the **cache-hit acceptance return itself** on session liveness (return the existing dead-backend error), plus a cheap entry check for fast-fail. Weak-fix challenge: an entry-only check leaves the race where death occurs during the convergence loop — the acceptance boundary is where the false success actually materializes, so that is where the gate belongs. The "labeled historical result" alternative invents a third response shape for a P2; refusing matches the existing dead-request behavior (tests/bridge.rs:78) and its message vocabulary. Residual: this fix removes the false *success*, it does not resurrect the backend and does not claim the cached diagnostics were wrong (that was never demonstrated). Probe: warm cache → kill probe-owned backend → `check_file` must error (not `Ok(count=0)`) in both direct and stdio faces; healthy warm-cache repeat-check control still returns Ok.

**R0-05 — blocked stdin write bypasses all deadlines (P1, Fix; agree, this is the round's hardest design).** *Observed*: synchronous `write_all`/`flush` (framing.rs:12-17) under the backend lock in `notify` (:549) and `request_locked` (:529); `check_file_impl` calls `sync_open` at :392 *before* creating its deadline at :400; `shutdown()` (:555) first performs `request("shutdown")` which needs the interaction+backend locks, so its 10 s reap loop at :566 is unreachable while a write blocks; 35.27 s no-return, external kill releases with `BrokenPipe`. Preferred minimal-coherent solution: **deadline-bounded nonblocking writes with kill-on-timeout as the single mechanism, applied at every write site** — set the child stdin fd nonblocking at spawn; `write_message` becomes a poll/write loop with a fixed total deadline (e.g. ~5 s — a live backend drains fast; the constant is policy, not tied to semantic timeouts); on timeout the caller marks the session `dead`, kills the child it owns, and returns the standard transport-death error. This bounds every lock hold, which in turn bounds `shutdown` (≤ write-deadline + write-deadline + 10 s) without restructuring shutdown itself, and preserves the current no-new-threads model. The writer-thread alternative (bounded channel + dedicated writer) is the textbook shape but adds thread lifecycle, queue policy, and shutdown ordering for the same observable guarantees — larger diff, defer unless the bounded-write loop proves awkward. **Scope trap the packet implies but doesn't name**: the reader thread *also* writes (server→client replies, session.rs:414-415) under the backend lock — a blocked reply write stalls diagnostics processing; the same bounded-write treatment must cover it (best-effort semantics preserved: on failure, drop the reply). Weak-fix challenge: a recv-side deadline already exists and demonstrably doesn't help; nonblocking writes without a kill path just convert the hang into the *next* caller's hang; and moving `sync_open` after deadline creation is cosmetic — the unbounded part is the write, not the ordering. Probe: the audit's blocked-write probe becomes the regression — 4 MiB didOpen + concurrent shutdown must both return within a bound derived from the write deadline (e.g. < 20 s), the child reaped, session `dead`; plus existing hover/diagnostic batteries green (frame integrity on the healthy path). Residual: a slow-but-alive backend receiving a huge document gets killed at the write deadline — an accepted, documented policy trade; graceful-shutdown latency is bounded, not zero.

**R0-06 — post-production stamp certifies unconsumed bytes (P1, Fix; agree with the packet's proposed shape, placement matters).** *Observed*: `stamp_meta_core` (engine.rs:1131 doc-set equality on *paths*, then :1146 hashing *current disk* into `indexed_source_identity`) runs at build.rs:720 *after* `merge_and_publish` (:687); the fixture's in-production same-path edit yields a graph with `old_name`, disk `new_name`, and `freshness fresh:true serves:current-tree` even with the identity cache off — the AIR-135.2 freshness verdict, the one thing this face exists to guarantee, is falsified. Preferred: **pre/post identity capture around production, compared before publish** — compute content identity (face set = this build's detected set) before spawning producers, recompute after legs validate, and only on equality proceed to publish→stamp→graph; on mismatch fail loud (`source mutated during production — rerun build`, env-class adjacent new variant), clean staged attempt, leave the prior slot untouched; the rerun converges by idempotence. Placement is load-bearing: the comparison must sit **before `merge_and_publish`**, otherwise you've already clobbered the slot you promised to protect. Weak-fix challenge: comparing mtimes pre/post reopens the mtime-preservation blind spot the identity EP just closed — it must be content identity; and on mismatch you must *reject*, never pick one side to stamp. Cost is acceptable (one extra walk+hash; the per-file hash cache makes the post-compute mostly cache-hits). Honest residual, and I want it recorded rather than papered over: two endpoint identities are *necessary, not sufficient* evidence of a stable read window — an ABA mutation (change mid-production, revert before post-hash) escapes detection, and producer-side read-time stamping is not portable (rust-analyzer/scip-typescript are external). Also assess the sibling paths as the packet asks: the auto-heal rebuild goes through the same build core and inherits the guard; `refresh` head-sync re-stamp (refresh.rs:120) has a narrower version of the same window (evaluate_staleness → stamp) — cheap tightening if it reuses the just-verified `snap.stamped_identity` on equality instead of recomputing, but this is optional scope; manual `--stamp-meta` stays a documented trust-based maintainer escape hatch. Probe: the run5 fixture as regression — in-production edit → build exits nonzero with the mutation message, prior slot intact, `freshness` stale with `content-drift` (never `fresh/current-tree`); unchanged-source control still exits 0 and stamps fresh. An ABA probe is explicitly *out of scope* — documented, not defended.

**R0-08 — battery false pass (P2, Fix; agree — and no oracle rewrite is needed).** *Observed*: live side takes the *last* space token (`2026-05-25)`), frozen side the *first* (`1.96.0`) — the pinned RA matches the frozen baseline yet reports drift; default mode early-returns and the harness counts it `1 passed`. **R0-09 — rollback comment promises retry; session is terminal (P2; contract narrowing, agree).** *Observed*: comment at session.rs:475 says killing the half-initialized backend "lets the next call retry fresh", but the killed child's EOF sets the shared `dead` flag (:390) and `ensure_spawned`→`check_alive` (:357) refuses — second request gets "restart the bridge"; a *new* session succeeds. The retry promise is a comment, not a user-facing contract, and no consumer need for same-session resurrection was identified (the wrapper restarts the bridge per harness session; init failure mid-session is rare). Preferred: amend the comment to the truthful terminal semantics in the same vocabulary R0-04 adopts ("dead is terminal; restart the bridge"), and **pin the contract with a regression** — reject-once backend → first request errors `initialize handshake failed`, second errors restart-required/`dead=true`, new session succeeds — so a future change can't silently alter the state machine. Weak-fix challenge, echoing the packet: a bare reset of the shared `dead` flag is not a fix — the flag has no generation notion, so a zombie reader from the old child can mark the new generation dead; same-session retry requires generation-fenced state (per-generation reader/pending/diag-cache) and is a separately-scoped feature if ever wanted. Dependency: none mechanically, but the amended wording and R0-04's death gate must agree on terminality.

**R0-10 — concurrent graph builds clobber one shared tmp name (P2; serialize writers, agree — unique temps are hygiene, not the fix).** *Observed*: fixed `graph.db.tmp-build` (graph_db.rs:749) is unlinked (:750) and opened (:758) by every explicit build; four concurrent builds → exits 1/1/1/0 (readonly-db, disk I/O ×2), final db integrity ok — crosstalk, not corruption. Source detail the packet doesn't name but that belongs to this design: the publication is **not complete at rename** — `materialize_derived` runs at :909 *after* the rename at :900, so (a) readers in that window see a db lacking derived rows that `detect_changes` hard-joins, and (b) a concurrent build's rename swaps the file under the first build's post-rename derived materialization. Preferred: **per-repo exclusive build lock held across the entire publication transaction** (tmp build → rename → derived materialization → `ensure_indexes`), with a bounded wait and a loud "concurrent build in progress" refusal on timeout — matching the single-writer reality the rest of the data plane already assumes (query-side heal has `.heal.lock` single-flight; umbrella staging has unique attempt names). Concurrent explicit builds then serialize (all four exit 0) or one refuses loudly — both defensible; incidental SQLite filesystem errors are not. Second change: move derived materialization (and everything else readers consume) **into the tmp artifact before the rename**, making the rename publish a complete artifact. Unique tmp names remain worth adding as belt-and-suspenders against stale-lock edge cases — but per the packet's own warning, and I concur, temps alone neither serialize generations nor close the post-rename window; the lock is the correctness mechanism. Weak-fix challenge: "unique temps only" is the tempting half-fix and it is insufficient twice over. Residual honesty: with different inputs racing, last-writer-wins at whole-build granularity remains possible (each publication internally complete — that is the invariant to claim, not per-input determinism); the same-input probe cannot adjudicate generation ordering and shouldn't be cited as if it could. Probe: 4-way concurrent explicit builds on the 5,000-node fixture → all exit 0 (serialized) or ≤1 loud busy refusal, never readonly/disk-I/O; integrity ok. Optional stronger probe if cheap to schedule: two-input variant asserts the final graph matches one complete generation, not a mix.

## Honest residual limitations (record, don't patch over)

Endpoint identity cannot see ABA/transient mid-production mutations, and external producers preclude read-time stamping (R0-06). Slow-alive backends die at the write deadline by policy; graceful shutdown is bounded, not instant (R0-05). Abandoned builds may still publish; cancellation abandons callers, not work (R0-03). Absent-graph-is-torn assumes no supported index-only face — true today because the graph build is unconditional and slot-absence has its own terminal state, but a future index-only feature needs a flag, not a silent predicate change (R0-07). R0-04 removes false success, does not demonstrate or fix wrong diagnostic *content*. R0-08 restores the oracle's teeth for exactly the two hover cases it covers — the "551 passed" baseline number remains an overstatement of exercised contracts even after this fix. R0-10 claims publication completeness and serialization, not cross-generation determinism.
