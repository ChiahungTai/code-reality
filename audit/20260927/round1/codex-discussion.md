R0-05 我不建議「把 deadline 移到 sync\_open 前面」就算修完，因為同步 write\_all 本身還是不可中斷；也不建議單純縮 recv\_timeout，因為目前根本還沒走到 receive。真正需要的 invariant 是：**deadline owner 必須能在不取得 blocked-writer mutex 的情況下 kill/reap child**。Writer thread 方案讓 ChildStdin 與 Child ownership 分開，正好建立這條能力；request timeout 也應變成從 write 前開始的一個 absolute deadline，而非「寫完才開始等 response」。

R0-06、R0-07、R0-10 最好當成同一條 publication boundary 設計。順序是「取得 producer-input identity A → stage → 再驗 A → 取得 writer ownership → 再驗 A → publish slot → stamp A → build/publish graph」。R0-07 再負責 crash/failure 後的 recovery invariant。這比各補一個局部 if 穩。尤其 build.rs (line 720) 現在的 stamp\_meta\_core 也被 refresh/head-sync/manual stamp 共用；若只修 build caller，manual restamp 仍可能成為 provenance laundering 的旁路。建議拆成「validated build stamp」與「head-only restamp」：後者只更新 HEAD 類 metadata，**保留既有 indexed source identity**；legacy index 沒有可信 identity 時，最保守是要求 rebuild，而非手動升級成 current-tree。

這裡有一個必須保留的誠實限制：R0-06 的 before/after hash fence 仍不是 immutable snapshot。A→B→A 的 ABA 期間，producer 理論上可能讀到 B，而兩端都是 A。若要保證「producer 確實讀了這組 bytes」，必須讓 producer 從 CR-owned immutable snapshot/copy 讀取，這是更大的 feature。這一輪可以承諾「偵測到 endpoint source drift 就不 publish，且 stamp 永不冒充另一個 identity」，不能承諾「producer input 是 transactionally immutable」。

R0-03 與 R0-09 我都認為 contract narrowing 是合理的本輪處置，但兩者要寫得精確。R0-03 關閉的是「cancel 是否等於停止/rollback」的錯誤期待；它沒有解決 producer 永久 hang。R0-09 關閉的是「同一 session 自動 retry」的錯誤承諾；它沒有提供 transparent backend restart。若 Arbiter 想要這兩項較強行為，都應另立 lifecycle scope，而不是塞進目前修復。

若只選一組最小但能 defend 的 acceptance suite，我會要求四個 adversarial probes：**stalled LSP writer 有總 deadline 且 child 被 reap；in-production source mutation 不 publish 且 manual restamp 洗不白；missing graph 被標 torn 並可 refresh 修復；四 concurrent graph writers 不再互踩。** 再加 R0-08 的 real RA battery 必須真的走到 hover assertions。這五個 probe 比單純再跑一次「551 passed」有意義，因為 R0-08 已經證明那個 aggregate count 本身不是 execution-depth oracle。

No changes applied. The strongest residual risks after these scoped fixes would still be ABA source mutation, MCP producer cancellation/rollback semantics, and a tiny R0-04 race before the reader has actually observed backend death；這些都不應被修復後的文件宣稱消失。
